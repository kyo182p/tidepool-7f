# tidepool-7f

Internal single-page tool. 靜態網頁（GitHub Pages）＋ Google Apps Script 後端（綁一份 Google 試算表）。網頁本身不放任何金鑰。

## 做什麼

1. 上傳 ShareX 長截圖（PNG 不限高度，可一次多張）→ 網頁切成約 1100 像素高的小片段，可先把敏感區塊塗黑。
2. 每個片段送到後端，由 Claude 看圖逐字轉錄成訊息（發言人、日期、時間、內文、引用、附件）。
3. 網頁把相鄰片段的重疊區對齊去重，給使用者校對、改字、刪錯誤訊息，然後存檔。
4. 後端依「對話群 × 日期」整理每日摘要（英文為主的對話給中英對照），並擷取英文單字給練習用。
5. 每則訊息記錄「是第幾次上傳出現的」，可以從摘要、單字、搜尋結果一路點回原文與上傳紀錄。
6. 附加檔案（對話裡的圖片、PDF）：用原解析度擷取內容（表格、名單、信件），原檔存到雲端硬碟「對話整理附件」資料夾，AI 先配對到所屬訊息、校對時可改；摘要會把附件內容算進去。
7. 每日另外抽出「事件」（期限、決策、突發、人員異動、船機設備），帶日期、相關人、主題名稱，主題名稱會沿用既有的，讓不同群組講同一件事時能串起來。
8. 信件：在「上傳分析」貼上 Outlook 原信（整串回覆會拆成一封一封）或 Copilot「匯出給對話整理」的結果，存到「信件」群組（跟 Teams 對話群分開），一樣產生每日摘要、單字、事件。同一封信重複貼不會重複存（日期＋寄件人＋主旨）；先貼 Copilot 版、之後再貼原信，會換成原文。
9. 信件 ↔ 對話：信件存檔後，AI 從前後 7 天的 Teams 訊息裡找講同一件事的（先用關鍵字挑最多 45 則候選，再讓 AI 判斷，附理由與把握程度）。對話存檔後，前後 7 天內的信件也會重新比對一次，所以先後順序不限。訊息旁的綠色／黃色標籤可以點過去看另一邊，配錯的按 ✕ 刪掉（之後不會再配回來）。
10. 排班工具的「問 AI」：雲林排班工具右下角的 💬 按鈕會呼叫這裡的 `ask` 動作（同一組代碼）。AI 需要資料時回 tool_use，由排班網頁在使用者電腦上查總表／出海計畫、算好再送回來；這裡只轉給 Claude，不存班表資料（只在「用量」記一筆）。排班規則寫在 `Code.gs` 的 `ASK_SYSTEM`，規則有變就改這段。
11. 期間報告：選日期區間與對話群，把事件串成整體走向、跨群組議題、期限時間軸、決策、突發、人員異動、待追問（後來有答案的會標出來），並列出資料涵蓋範圍；可複製成文字或列印。還沒抽事件的天會在產生報告前自動補抽。

## 試算表工作表

| 工作表 | 內容 |
|---|---|
| 使用者 | 代碼（等於密碼）、名稱、啟用 |
| 群組 | 對話群 ID、名稱、說明、啟用、訊息數、日期範圍、類型（chat／mail） |
| 訊息 | 每則訊息一列；「出現的上傳」記錄每次上傳 ID |
| 摘要 | 對話群 × 日期一列，JSON 欄是完整摘要 |
| 單字 | 每個單字一列，含例句、出處訊息、上傳 ID |
| 附件 | 每個附件一列：對應的訊息、雲端硬碟檔案、擷取內容 |
| 單字標記 | Tina 對單字的標記（重要／略過）與練習紀錄（練習次數、答對、答錯、最近 10 次結果） |
| 事件 | 每日抽出的事件（類型、事件日期、主題、狀態、嚴重度、出處訊息） |
| 報告 | 期間報告（JSON 分段存在 JSON1～JSON6） |
| 上傳紀錄 | 每次上傳一列 |
| 信件 | 每封信一列：訊息ID（對應「訊息」工作表）、寄件人、收件人、主旨、來源（original／copilot） |
| 相關對應 | 信件訊息ID ↔ 對話訊息ID、理由、把握（high／medium）、狀態（ok／removed） |
| 用量 | 每次 AI 呼叫的 token 與估計美元 |

## 部署

1. **API Key**：platform.claude.com → Create Key（可沿用 family-quiz 那把）。
2. **試算表＋Apps Script**：新增一份試算表 → 擴充功能 → Apps Script → 把 `apps-script/Code.gs` 整份貼上 → 選 `setup` 執行 → 授權。
   - 會建立所有工作表、兩組代碼（「使用者」工作表）、16 個預先建好的對話群（依 Tina 的 Teams 側欄），以及雲端硬碟的「對話整理附件」資料夾（第一次會要求雲端硬碟權限）。
3. **指令碼屬性**：專案設定 → 指令碼屬性 → 新增 `ANTHROPIC_API_KEY`。
4. **部署**：部署 → 新增部署作業 → 類型「網頁應用程式」→ 執行身分「我」→ 誰可以存取「所有人」→ 複製 `/exec` 網址。
5. **前端**：`index.html` 裡 `const CONFIG = { API_URL: '' };` 填入 `/exec` 網址 → push → repo 設定 Pages（main / root）。
6. **測試**：開網頁 → 輸入「使用者」工作表裡的代碼 → 上傳一張截圖。

### 更新規則

- 改 `index.html`：push 後幾分鐘生效。
- 改 `Code.gs`：部署 → **管理部署作業 → 編輯（鉛筆）→ 版本：新版本 → 部署**（網址不變；不要「新增部署作業」）。
- `setup()` 可以重複執行，只補缺的部分。新版程式用到新權限（例如雲端硬碟）時，貼上後先在編輯器執行一次 `setup` 完成授權，再部署新版本。

## 限制與參數

- `UrlFetchApp` 單次呼叫約 60 秒逾時：所以轉錄一次只送一片（約 1400×1100），摘要與單字分成兩個呼叫。片段逾時或回應被截斷時，網頁會自動把那一片切成上下兩半重送。
- 模型在 `Code.gs` 開頭的 `MODELS`（目前三項都用 `claude-opus-5-5`，精準優先）；`PRICE` 只用來估算用量。
- 網頁端參數在 `index.html` 開頭：`SEG_H`（片高）、`SEG_OV`（重疊）、`MAX_W`（寬度上限）、`CONC`（同時送幾片）。
- 沒有每日次數限制；用量看「用量」工作表與 Claude Console。
- 信件配對參數在 `Code.gs` 開頭：`LINK_WINDOW`（前後幾天）、`LINK_CANDS`（候選上限）。每封信比對一次大約 0.02–0.05 美元。
- 單字：Tina 標成「★ 重要」的才會出練習題（英翻中、中翻英、例句填空，弱的先出）；「略過」的會隱藏，之後擷取新單字時也不再挑。練習結果存在「單字標記」工作表，可以從這裡看學習狀況。
